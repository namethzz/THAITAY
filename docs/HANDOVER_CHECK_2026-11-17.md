ใช้ราคาจริงชุดปัจจุบันและ forecast จาก Git history ไม่สร้างคำพยากรณ์ย้อนหลังขึ้นมาใหม่เพื่ออ้างว่าเป็นผลสอบจริง

| ไฟล์พยากรณ์ | MAPE | ครอบคลุมช่วงราคา | ป้ายถูก |

ราคาและป้ายเหมือนเดิม แต่ช่วงราคาเปลี่ยน จึงต้องระบุเวอร์ชันเมื่อรายงาน coverage ไม่ใช้ผล 100% ของฉบับที่ปรับแล้วแทนผลของฉบับเก่า ดู [รายงานฉบับเก่า](checks/2026-11-17/live_check_archived.md) และ [รายงานฉบับปรับช่วง](checks/2026-11-17/live_check_revised.md)

ข้อจำกัด: เป็นการเทียบ artifact ที่มีใน Git ไม่ได้ยืนยันเวลาที่ผู้ใช้เห็นจริงบน Vercel หรือวันที่ สนค. ประกาศ และไม่ใช่ผล prospective รอบใหม่ เดือน พ.ย. ยังไม่มีราคาจริงให้สอบ

ผล backtest ของ LightGBM ใช้สำหรับยืนยันว่ารันได้ ยังไม่รับรองความแม่นยำใหม่: โค้ดปัจจุบันปรับเทียบความน่าจะเป็นจากผลย้อนหลังชุดเดียวกับที่ใช้รายงาน precision มีความเสี่ยงประเมินดีเกินจริง ควรแยกช่วงฝึก/ปรับเทียบ/ทดสอบตามเวลา และประเมินฟีเจอร์ตามเวลาที่ข้อมูลมีจริงก่อนเปลี่ยนโมเดล production

## คำสั่งตรวจซ้ำ

PowerShell จาก root ของ repo:

```powershell
ml/.venv/Scripts/python.exe -X utf8 -m unittest discover -s ml/tests -v
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix frontend audit
```

งานรายเดือนให้ใช้ Git Bash จาก `ml/` หลังเปิด virtual environment:

```bash
source .venv/Scripts/activate
export PYTHONUTF8=1 PYTHONIOENCODING=utf-8
bash monthly_update.sh
```

ไม่มีเดือนใหม่: exit 3 เป็นปกติ อย่าฝืนแก้วันที่หรือข้ามเงื่อนไขในระบบเผยแพร่ หากมีเดือนใหม่ให้อ่าน `out/live_check.md`, `out/factors_update.md`, `out/data_report.md` และแนบรายงานใน PR เพราะ `out/` ไม่ถูก commit
