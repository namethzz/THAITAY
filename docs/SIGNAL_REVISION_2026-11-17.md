# แก้ปัจจัยค้างและการประเมินป้าย — 17 พ.ย. 2569

Branch `fix/signal-factors-temporal-calibration` — แก้เฉพาะเส้นทางป้ายของ THAI TAY เดิม ไม่ใช่การทดลอง OwnML ที่ยกเลิกไปแล้ว

## สิ่งที่เปลี่ยน

1. ตัด `newcastle_coal_usd_ton`, `steel_futures_unverified`, `scrap_metal_ppi_index` ออกจากฟีเจอร์และไฟล์ใช้งานรายเดือน ไม่เติมค่าค้างแทนเดือนใหม่ ไม่เปลี่ยนไปใช้ดัชนีหรือสัญญาที่หน่วยไม่ตรงกัน
2. ใช้ Brent, USD/THB, CNY/THB, แร่เหล็ก และดีเซล 5 ปัจจัย ดาวน์โหลดประวัติเพียง 5 ไฟล์ และตรวจว่าการอัปเดตเดือนล่าสุดครบ เป็นค่าบวกและ finite ก่อนเขียนไฟล์
3. หยุดเลื่อนเดือนปัจจัยย้อนกลับ ใช้เดือน t-1 หรือก่อนหน้าอย่างสม่ำเสมอทั้งชุด 5 และ 8 ปัจจัย
4. แยก calibration/test ตามเวลา ใช้ตัวปรับเทียบและ baseline ที่เรียนจาก calibration เท่านั้น ไม่ใช้คำตอบ test มาปรับคะแนนความน่าจะเป็นหรือเลือก threshold
5. เส้นทางป้ายไม่ใช้ interpolation ของ `baseline.monthly` เพราะวิธีเดิมอาจใช้ราคาหลังช่องว่างมาคำนวณฟีเจอร์/actual และใช้ช่องว่างในอนาคตเลือกว่าจะเก็บประวัติช่วงไหน การเปลี่ยนนี้ใช้เฉพาะป้าย; default ของสคริปต์ทดลองราคาเดิมยังเหมือนเดิม
6. ไม่เลือกเฉพาะวัสดุที่ยัง active ณ วันสิ้นสุดมาเป็นข้อสอบทุกเดือนย้อนหลัง ใช้วัสดุที่มีราคา origin และ target จริง ณ เดือนที่ประเมิน

เลือกตัด 3 ปัจจัยเพราะแหล่ง/หน่วยยังไม่ยืนยันและอัปเดตต่อเนื่องไม่ได้ ไม่ใช่เลือกชุดจากคะแนน test

## วิธีประเมินที่กำหนดก่อนรัน

- ข้อมูลราคาจริงถึง ต.ค. 2569
- Calibration: origins ทุก 3 เดือนตั้งแต่ ม.ค. 2562 ถึง ก.ค. 2568; target ต้องไม่เกิน origin แรกของ test
- Test: origins รายเดือน ต.ค. 2568–ก.ย. 2569 เฉพาะ horizon ที่มีราคาจริงแล้ว จึงมี 12/11/10 origins สำหรับระยะ 1/2/3 เดือน
- Calibration target ล่าสุด: ส.ค./ก.ย./ต.ค. 2568 ตามลำดับ ทั้งหมดรู้ได้ก่อนหรือ ณ origin แรกของ test ต.ค. 2568
- classifier ฝึกใหม่แต่ละ origin ด้วย label ที่ target ≤ origin เท่านั้น; calibrator ตรึงตลอด test รวมถึงตอนสร้างป้ายปัจจุบัน
- bins `[0, .3, .5, .7, .85, 1.0001]`, threshold 70%, bin น้อยกว่า 30 จุดใช้ prior จาก calibration; ไม่จูนหลังเห็นผล
- category baseline และ constant baseline ใช้ calibration เดียวกัน ห้ามใช้ความถี่ราคาเปลี่ยนใน test เป็น baseline
- เทียบ 5 ปัจจัยกับ 8 ปัจจัยด้วย code path, lag, seed, hyperparameters, เดือน/วัสดุ/actual ชุดเดียวกัน ไม่มีการรันสองการทดลองแย่ง CPU พร้อมกัน

## ผลทดสอบ

Precision = ขึ้นป้ายแล้วราคาเปลี่ยนจริงกี่ %; Recall = จับเหตุการณ์ราคาเปลี่ยนได้กี่ %; Brier วัดความคลาดเคลื่อนของความน่าจะเป็น ค่ายิ่งต่ำยิ่งดี

| ระยะ | ชุดปัจจัย | ขึ้นป้ายถูก/ทั้งหมด | Precision | Recall | Brier |
|---|---|---:|---:|---:|---:|
| 1 เดือน | 5 ที่รองรับ | 148/212 | 69.81% | 20.33% | 0.178748 |
| 1 เดือน | 8 เดิม | 305/415 | 73.49% | 41.90% | 0.183526 |
| 2 เดือน | 5 ที่รองรับ | 384/477 | 80.50% | 37.35% | 0.245015 |
| 2 เดือน | 8 เดิม | 361/455 | 79.34% | 35.12% | 0.241040 |
| 3 เดือน | 5 ที่รองรับ | 435/461 | 94.36% | 37.05% | 0.230638 |
| 3 เดือน | 8 เดิม | 393/437 | 89.93% | 33.48% | 0.226609 |

จำนวนข้อสอบแต่ละระยะ 2,228 / 2,035 / 1,843 จุด และจำนวนเหตุการณ์เปลี่ยนราคา 728 / 1,028 / 1,174 จุด ทั้งสองชุดตรงกันทุก key และ actual

**ไม่พบว่าชุด 5 ปัจจัยแม่นกว่าทุกระยะหรือทุกตัวชี้วัด**: ระยะ 1 เดือน precision/recall ลดลง ส่วนระยะ 2–3 เดือน precision/recall เพิ่ม แต่ Brier แย่ลงเล็กน้อย การแก้รอบนี้ทำให้แหล่งข้อมูลดูแลได้และการประเมินตรงไปตรงมาขึ้น ไม่ใช่หลักฐานว่าเพิ่มความแม่นยำโดยรวม

Baseline ตามหมวดที่ไม่ใช้ LightGBM มี precision/recall 74.84%/31.46% ที่ระยะ 1 เดือน และ Brier 0.176055 ดีกว่าโมเดล 5 ปัจจัยในรอบนี้ จึงยังไม่มีเหตุผลอ้างว่า LightGBM ชนะวิธีง่ายเสมอ ไม่เปลี่ยนไปเลือก baseline หรือปรับ threshold จากผล test นี้

ตัวเลข 80% จากรายงานป้ายรุ่นเก่าไม่ควรเทียบเป็นก่อน/หลังโดยตรง เพราะรอบนี้แก้ทั้งการแบ่ง calibration/test, factor lag, observed labels และ population แล้ว ส่วนชุด 8 ปัจจัยในตารางคือการรันใหม่ด้วยกติกาเดียวกัน ไม่ใช่คะแนนเดิมที่ปรับเทียบและวัดบนชุดเดียวกัน
